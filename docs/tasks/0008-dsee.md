# 0008 DSEE (upscaling)

## Goal
Read and set DSEE (OFF / AUTO) when the headset advertises it.

## Why
Owner's MVP list. Small feature, but its existence on XM6 is unconfirmed, so it must be strictly capability-gated.

## Scope
- Function `UPSCALING_AUTO_OFF` 0xE2 (T1). GET `E6 01` -> `E7 01 <OFF 0x00|AUTO 0x01>`, SET `E8 01 <value>`, status `E2 01` -> available/disabled.
- If status says disabled/unavailable, show unavailable and do not send SET.
- Dev CLI `--get dsee`, `--set dsee off|auto`.
- Allowlist: `E6 01`, `E2 01` (GET), `E8 01` (SET) only. Note `E8 03|09|04|06|07` (listening modes) stay OFF the allowlist (BGM + Voice Control reboot hazard on XM6).

## Out of scope
"DSEE Extreme" as a separate value (the protocol only has OFF/AUTO), listening modes (BGM, upmix, sound-leak), connection-quality mode `E6 00|02|05`.

## XM6 status
**Unknown**: the XM6 support doc does not list DSEE; implement only if 0xE2 is in the T1 list from the capture. If it is not advertised, the task closes as "not available on XM6" with the code reduced to the gating and parser (or dropped; owner decides).

## Acceptance
(a) Unit tests: parse both values; unknown value kept as an error; SET bytes; not advertised gives None and no traffic; unavailable status blocks SET; guard accepts `E8 01` and rejects `E8 03`, `E8 09`, `E8 04`, `E8 06`, `E8 07`; NTFY updates state.
(b) Owner: only if advertised. Toggle OFF/AUTO and report; DSEE is hard to hear, so also confirm the setting persists on the phone app/headset or on re-read. If not advertised, report that and close.

## Open owner decisions
- If 0xE2 is absent: recommend dropping DSEE from the MVP and the UI.
